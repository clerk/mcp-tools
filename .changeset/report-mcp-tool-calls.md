'@clerk/mcp-tools': minor
---

Add `clerkInstrumentHandler` and `clerkInstrumentServer`, which report MCP tool calls to Clerk's Backend API for MCP analytics and the audit log.

- `clerkInstrumentHandler(handler, options)` from `@clerk/mcp-tools/express`, `/hono`, and `/next` authenticates each MCP request as `mcpAuth` and `withClerkMcpAuth` do, then serves it with the handler `createMcpHandler` from `@modelcontextprotocol/server` returns, the route handler from `mcp-handler`, or a handler of your own. Express serves an MCP SDK 2.x handler through `toNodeHandler` from `@modelcontextprotocol/node`, a new optional peer dependency.
- `clerkInstrumentServer(server)`, called where each MCP server is created, lets the handler see its tool calls. Tools registered after it also report their handler's time, and a handler that throws is reported with the error code `thrown:<ErrorClass>`, told apart from a returned `isError` result, and a call to a tool the `McpServer` does not have is reported with the error code `not_found`.
- `clerkInstrumentServer` also reports each `initialize`, or `server/discover` on protocol revision 2026-07-28, as a `client_initialized` event with the client's name and version and the protocol version, each list request as a `list_request` event with its item count, each resource read as a `resource_read` event named by the registered resource or URI template it matched, or the URI's scheme, never the URI asked for, and each prompt get as a `prompt_get` event with the prompt's name and message count. Resources and prompts registered after it report their handler's time and thrown errors as tools do.
- The new `reporting` option turns reporting on, off by default. Its options object turns off the IP address, `User-Agent`, or Clerk identity, picks which tools are reported, and names the server. Reports go to `POST /v1/mcp_events` as `tool_call` events in batches, after the response, and never send tool arguments, results, or error messages.
- With `reporting` on, `clerkInstrumentHandler` also reports each `401`, `403`, and `421` it answers as an `auth_failure` event, with the reason, the HTTP status, the verifier's code, and the JSON-RPC method and tool name read from a copy of the body after the answer is sent. It never changes or delays the answer, and auth failures are capped and queued apart from tool calls.
- `mcpAuth`, `streamableHttpHandler`, and `withClerkMcpAuth` are deprecated, and refuse `reporting` with a `Clerk error:`.
