Add Server Card discovery (beta). `generateServerCard` in `@clerk/mcp-tools/server` builds an MCP Server Card from a validated, supported subset of the extension: name, version, description, optional title, website, icons, repository, and namespaced JSON `_meta`, with a generated `$schema` and static streamable HTTP remote. Public repository, website, and HTTP icon URLs reject credentials, while website fragments remain allowed. `serverCardHandler` in `@clerk/mcp-tools/hono` and `@clerk/mcp-tools/next` serves it with public CORS, a weak `ETag` and conditional `GET`/`HEAD`, configurable public caching (an hour by default, with invalid values including `null` rejected at setup), and a `421` for an origin no listed `resourceUrl` has. Versions may be free-form or carry `x` labels in prerelease or build metadata, but version ranges are rejected. Every error is sent with `Cache-Control: no-store`. Discovery responses preserve `ETag` exposure and error `no-store` when earlier middleware sets CORS or cache headers. Neither needs Clerk keys or an MCP SDK.

Add AI Catalog discovery (beta). `generateAICatalog` in `@clerk/mcp-tools/server` builds a minimal AI Catalog (`specVersion` `0.9`) against the v0.9 release candidate pinned at Agent-Card/ai-catalog@19208af (#141); `1.0` is reserved for the final specification. Entries link one MCP Server Card by an explicit logical identifier, a required `displayName` (optional in the RC, but required by Agentic Resource Discovery v0.91), and an https card URL (plain http only on a loopback host, for local development), which may be on another host and is never fetched. Card URLs must be exact absolute URLs, without WHATWG URL repair or unescaped Unicode or malformed percent escapes. The RC recommends `urn:air:{publisher}:{name}[:{kind}]`; this open identifier format is not enforced as a required scheme. `aiCatalogHandler` in `@clerk/mcp-tools/hono` and `@clerk/mcp-tools/next` serves it as `application/ai-catalog+json` with the same public CORS, conditional requests, and caching as `serverCardHandler`. The Next.js route handlers answer every method a route exports, including their own CORS preflight, so export one handler as `GET`, `HEAD`, `OPTIONS`, and the other methods.

Serve both through Express. `serverCardHandler` and `aiCatalogHandler` in `@clerk/mcp-tools/express` answer as the Hono handlers do, selecting a listed `resourceUrl` by the origin Express gives the app (`X-Forwarded-*` only under `trust proxy`), and answering a request without a `Host` header that parses with a `400` only when a list of `resourceUrl`s needs its origin. The Express Server Card handler varies on forwarded host and protocol headers when a trusted proxy selects a listed resource URL for an origin-form request, by the same rule as the protected-resource metadata handler: only when Express trusts the immediate peer.
