**Breaking:** raise the optional `@modelcontextprotocol/sdk` peer and development dependency floors to `^1.32.0`, and the optional `@modelcontextprotocol/server` peer floor to `^2.3.0`, for upstream security fixes (GHSA-jm63-cq47-j5jp, GHSA-46jr-4wx8-v453 and GHSA-rvq5-wwqv-78pq affect `@modelcontextprotocol/server` >=2.0.0 <2.3.0). SDK 2.x users now need `@modelcontextprotocol/server` 2.3.0 or later. Preserve the SDK's issuer-bound OAuth client information and tokens across stored sessions. Client credentials are bound to an authorization server before any authorization code is exchanged: dynamically registered credentials to the server that issued them, and known credentials to the server the MCP server names when authorization starts. A session's authorization code, client secret and refresh token are sent only to the server it is bound to, and a bound session does not register at another. Sessions that are not bound, because an earlier version stored them or a sign-in was in progress during the upgrade, keep their access token until it is rejected, but their refresh token and client secret are not sent to any authorization server and `completeOAuth` throws for them: reconnect once with `createKnownCredentialsMcpClient` or `createDynamicallyRegisteredMcpClient`. HTTP clients use the SDK's safer redirect policy; configure the final MCP endpoint URL when a deployment redirects across origins (or redirects in a browser).
